The launcher and the panels below are surfaces inside the already-running Quickshell, reached through Hyprland's global-shortcuts protocol rather than by running a command — so a keypress starts no process. With Quickshell down they do nothing at all, which is the same harmless failure as an unbound key.

Focus mode changes a setting rather than showing a window, so it survives a shell restart — and the bar keeps a visible button to leave it, because a mode entered by accident must not need a second secret key to undo.
The power button is deliberately not locked: with the screen locked it stays inert, so no shutdown menu can be raised over the lock screen.

Right drags, left resizes — the opposite way round from the Hyprland default. Moving is done constantly and resizing occasionally, and the right button is the one a free hand finds without looking. Both still need SUPER: a bare right drag would stop right-click reaching applications at all, so no context menus anywhere.

The scrolling layout

SUPER+J
Cycle the focused column's width
SUPER+[
Consume — pull the next column's window into this one
SUPER+]
Expel — push it back out into its own column
SUPER+A
Fit all — the whole strip on one screen
Windows live in a horizontal strip of columns rather than a tree, and several can share one column — that is the layout's main trick. SUPER+A is how you find a window once the strip is longer than the screen.

Volume, light and media

Vol ±
±5%, clamped at 100% so it never software-amplifies
Mute
Mute the output
Mic mute
Mute the microphone
Bright ±
±5% on a 4th-power curve, never fully dark
Play/Pause
Play / pause
NextPrev
Next / previous track
All bound with locked = true, so they keep working on the lock screen — which is where media keys are most useful. Each changes the value before asking for the on-screen display, because the OSD reads the real number from PipeWire or sysfs; announcing first would show the old one. The OSD is decoration, never a dependency.
Brightness goes through bin/backlight.sh, which resolves the panel from /sys/class/backlight — amdgpu_bl1 here, intel_backlight elsewhere, nothing at all on a desktop, where these keys correctly do nothing rather than needing to be deleted.

Passthrough — VMs

SUPER+Escape
Toggle the passthrough submap
A VM — or another Wayland session — inside this one means two compositors competing for SUPER, and the host always wins. While passthrough is active none of the binds on this page exist, so every key goes straight to the focused window.
A stuck passthrough looks exactly like a broken keyboard. hyprctl submap says which submap is active, and SUPER+Escape is the only bind the submap defines — the same key always gets you out.
